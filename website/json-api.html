Read and write your file as JSON

Read and write parts of your HTML file as JSON from the page itself or another program.

Let's say your file is a task list that has a heading and two tasks. A program on your computer can read the heading and tasks as JSON and write new ones back.

The file holds the data. Rules map CSS selectors to JSON keys. HTML Clay reads the matching parts of the file and returns their values. To write, send JSON with the same keys. HTML Clay writes each value into the part of the file its rule selects and saves a version. Open tabs pick up the change through the ClayJS sync plugin.

There are three ways to use the JSON API:

  1. Call ClayJS from the page itself.
  2. Send rules with each request. The file needs no changes, so this works on any HTML file.
  3. Save rules in the file. Then a program can ask for the file's JSON without knowing its structure.

The page shows this list:

Output
Today

1. Buy milk
2. Book tickets

Both ways return these values. Responses here are formatted for reading:

JSON
{
  "title": "Today",
  "items": ["Buy milk", "Book tickets"]
}

You need HTML Clay running on macOS, Linux or Windows. The terminal examples use curl in Bash or Zsh. On Windows, use a Bash terminal for these commands. If you have not opened an HTML Clay file yet, start with Get started.

Save the example file

Save this as todo.htmlclay in your home folder, then open it with HTML Clay:

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Tasks</title>
</head>
<body>
  <h1>Today</h1>
  <ol>
    <li class="todo" data-done="no">Buy milk</li>
    <li class="todo" data-done="no">Book tickets</li>
  </ol>
  <script src="https://clayjs.com/v1/clay.js?plugins=sync"></script>
  <script src="https://clayjs.com/v1/clay-data.js"></script>
</body>
</html>

The ClayJS script enables live updates. Plain .html files work the same way.

From the page itself

To try it without writing code, download the JSON demo and open it with HTML Clay: edit the recipe and its JSON updates, edit the JSON and press Write and the recipe updates.

Code in the todo page can read its live content, read the saved file and write changes back:

JavaScript
(async () => {
  await clay.ready;
  await clay.loaded.data;
  const rules = { title: "h1", items: ".todo[]" };
  const live = clay.extractData(rules);
  const saved = await clay.readData(rules);
  await clay.writeData({ ...saved.data, title: "Tomorrow" }, {
    rules,
    ifMatch: saved.etag
  });
})();

Save ordinary page edits before calling clay.writeData(). After the write, ClayJS updates the open page without a reload.

Read with rules in the request

Replace PORT with the port in your open tab's address. Your tab's address looks like http://127.0.0.1:PORT/todo.htmlclay.

Run this in your terminal:

Terminal
base='http://127.0.0.1:PORT'
curl --get "$base/todo.htmlclay" \
  --data-urlencode 'data={"title":"h1","items":".todo[]"}'

Keep that terminal open for the following examples.

The data parameter carries the rules, which curl encodes for the URL. title reads the heading. The [] in .todo[] collects every matching task's text. The response is the JSON shown above.

Ask only for the keys you need. With data={"title":"h1"}, the response contains only title:

JSON
{"title":"Today"}

Write with rules in the request

The next request changes the heading to "Tomorrow" and the first task to "Buy bread".

Send the rules in the URL and the new values as the body:

Terminal
curl "$base/todo.htmlclay" \
  --url-query 'data={"title":"h1","items":".todo[]"}' \
  -H 'Content-Type: application/json' \
  --data '{"title":"Tomorrow","items":["Buy bread","Book tickets"]}'

The --data option makes this a POST, and --url-query encodes the rules into the URL. HTML Clay returns the updated values:

JSON
{
  "title": "Tomorrow",
  "items": ["Buy bread", "Book tickets"]
}

Open todo.htmlclay in your text editor. The heading now contains Tomorrow, and the first task contains Buy bread. The open tab updates too. The rules you sent are not saved into the file.

A key you leave out is left alone. An array you send becomes the whole list: a task missing from it is removed, and a new task is a copy of the first task's element, with your text inside it. Keep at least one task in the list because once the list is empty, a write cannot add tasks back. New text replaces what was inside the selected element. Each write that changes the file is saved as a version.

Writes reach only the elements the rules select, and only their content. They cannot write scripts, styles or event handlers. HTML you send is saved as plain text. A key the rules do not define causes a 400 response. Keep the JSON body under 1 MB.

Save the rules in the file

When several programs use the same file, put the rules in it once. Add this tag inside the file's <head>:

HTML
<script type="application/json" data-rules-name="api" data-rules-version="1">
{
  "title": "h1",
  "items": ".todo[]"
}
</script>

Now ask for the file through /_/api/, with no data parameter. Put /_/api/ between the port and the file name:

Terminal
api="$base/_/api/todo.htmlclay"
curl "$api"

/_/api/ reads the tag named api and returns the same JSON. Writes work the same way, without the rules in the URL:

Terminal
curl "$api" \
  -H 'Content-Type: application/json' \
  --data '{"title":"Tomorrow","items":["Buy bread","Book tickets"]}'

Which rules apply

Rules sent with a request replace the file's tag for that request, on either URL. They are never merged with the tag. /_/api/ uses the tag only when the request has no data parameter.

An empty, malformed or repeated data parameter returns 400. HTML Clay never falls back to the tag.

Write only if the file is unchanged

Change the second task only if the file still matches your read. First, read with response headers:

Terminal
curl -i "$api"

The Etag header identifies the file you read. Both URLs return it, for reads and writes. Its value looks like this:

Output
Etag: 8f02c16e7b4d9a30

Replace the sample value below with your exact Etag, then change the second task:

Terminal
curl "$api" \
  -H 'Content-Type: application/json' \
  -H 'If-Match: 8f02c16e7b4d9a30' \
  --data '{"title":"Tomorrow","items":["Buy bread","Book train tickets"]}'

If the file still matches, the response shows the changed task:

JSON
{
  "title": "Tomorrow",
  "items": ["Buy bread", "Book train tickets"]
}

If the file has changed, HTML Clay returns 412 and writes nothing. Read the file again before deciding what to send. Without If-Match, the write skips this check.

Rules reference

Each rule selects a value from the file. These forms work in the data parameter or the rules tag:

Form Example Value read
sel "h1" Text of the first match
sel[] ".todo[]" Text of every match, as an array
sel@attr ".todo@data-done" An attribute on the first match
[sel, {...}] [".todo", {"text": ".", "done": "@data-done"}] One object per match

To read text and completion together, use these rules:

JSON
{
  "title": "h1",
  "items": [".todo", {"text": ".", "done": "@data-done"}]
}

Inside each task, . reads its text and @data-done reads its attribute. The next read returns:

JSON
{
  "title": "Tomorrow",
  "items": [
    {"text": "Buy bread", "done": "no"},
    {"text": "Book train tickets", "done": "no"}
  ]
}

Use that object shape for subsequent writes too. To mark the first task done, send this body:

JSON
{
  "items": [
    {"text": "Buy bread", "done": "yes"},
    {"text": "Book train tickets", "done": "no"}
  ]
}

Who can read and write

A program on your computer can read and write through this API. If you can open the page in your browser, you can read it through the API.

A trusted folder is one you have allowed HTML Clay to save files in. Writes require an opened file, or a .htmlclay file in a trusted folder.

A save token is the identifier HTML Clay gives a page to let it save its file. A browser page sends the target file's token in a Save-Token header. A program on your computer needs no token.

Other websites cannot read the API through your browser. HTML Clay sends no CORS permission headers and refuses requests from other websites that try to write. A page HTML Clay serves on the same port can read it.

Hyperclay Local serves the same URLs for the files in its folder, for reads and writes.

Troubleshooting

  • 400 for an unknown key: the key is not in the rules you used. Send a key the rules define.
  • 400 for the data parameter: it is empty, malformed or sent twice. Send it once, with valid rules.
  • 405 on a POST to the file's own address: add the data parameter, or post to /_/api/.
  • 403 on a write: open the file in HTML Clay or put it in a trusted folder. A browser request also needs the file's save token.
  • 412 on a write: read the latest file, then revise your change and retry with its new Etag.
  • The file changed but the tab did not: check that the ClayJS script loads the sync plugin.
